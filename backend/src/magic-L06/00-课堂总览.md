# L06 统一内容模型与普通发帖：课堂总览

> 这一课只做一件事：**让主人能发一篇普通帖**。
> 拆成 4 个 HTTP 接口，每个接口从 Controller 往下打穿到数据库。

---

## 本课在哪、边界、禁止项

- **主线位置**：M2「能看的论坛」第一课。M1 地基（L00–L05）已完工，项目能启动、能登录。
- **边界**：只做主人**普通发帖闭环**（建草稿 → 看草稿 → 发布 → 看详情）。
- **不碰**：AI 协作投稿（L15+）、评论（L08）、点赞（L09）、Feed 列表（L07）、图片上传（L11）。
- **禁止项**：🚫 **禁止给 post 表加 content 字段**。正文存 contribution/draft_block/post_version_block，不存 post 行里。

## 验收（靠你亲手跑后端 curl，不靠你写测试）

- [ ] 普通帖子闭环：建草稿→发布→读者能看到
- [ ] 发布版本不可覆盖：发布后改草稿，已发布内容不变

---

## 4 个接口（本课的全部）

| # | 接口 | 作用 | 核心难度 |
|---|---|---|---|
| ① | `POST /api/v1/owner/drafts` | 建草稿（TX-01） | 🔴 一个事务写 4 张表 |
| ② | `GET /api/v1/owner/drafts/{id}` | 看自己的草稿 | 🟢 读 + 拼 DraftView |
| ③ | `POST /api/v1/owner/drafts/{id}/publish` | 批准发布（TX-02） | 🔴 复制快照、版本不可覆盖 |
| ④ | `GET /api/v1/public/posts/{id}` | 读者看已发布的帖 | 🟡 读快照表 |

## 顶层调用链（每个接口都是这条链，从上到下）

```
HTTP 请求
   │
   ▼
Controller    ← 入口：拿当前登录用户、收 DTO、调 Service、返回 DTO
   │  (入参 Request DTO)
   ▼
Service       ← 业务编排 + @Transactional 事务边界（本课真正的硬核）
   │  (调多个 Mapper)
   ▼
Mapper        ← 持久化，MyBatis-Plus 白送 CRUD（已就绪）
   │
   ▼
DO / 数据库表  ← 库行映射（已就绪：7 个 DO + V004/V005 表）
   │  (出参 View / Response DTO)
   ▼
HTTP 响应
```
