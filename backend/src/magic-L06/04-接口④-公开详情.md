# 接口④ 公开帖详情 `GET /api/v1/public/posts/{postId}`

> **一句话**：让**任何人（不用登录）看一篇已经发布的帖子**。
> 它是"读者端"——前面①②③都是作者在后台操作，这个接口是普通访客点开一篇帖子看到的内容。

---

## 先看这个接口广义上在干啥

```
作者侧（①②③，要登录）           读者侧（④，不用登录）
  建草稿 → 看草稿 → 发布   ───→    看已发布的帖子
                          这一棒
```

发布（③）把草稿冻成了"快照"。接口④就是把那份**快照**读出来给访客看。
关键一句：**它读的是 post_version_block（发布快照），不是 draft_block（草稿）**——所以作者之后改草稿，访客看到的不变。这是整课验收"发布不可覆盖"的最后验证点。

---

## 自顶向下：从 Controller 往下推

我们先站在最表层（HTTP 入口），一层层往下问"那它需要谁"，自然推导出要写的东西。

```
①  PublicPostController.getPost(postId)        ← HTTP 入口（最表层，先写它）
        │ 它要调谁？
        ▼
②  ContentService.getPublicPost(postId)        ← 业务：顺指针读快照
        │ 它要返回什么给前端？
        ▼
③  PublicPostView（出参）                        ← 读者看到的数据形状
        │ 它内部装正文块，用谁？
        ▼
   ContentBlockView（①②已写好，直接复用）         ← 不用再写
```

**和前几个接口的不同点（先记住，写的时候不踩坑）**：
- 路径 `/public/**` → L05 安全配置是 **permitAll**，匿名可访问。所以 Controller 里**没有 `CurrentUser.requireId()`**，也**没有行级授权**（公开的东西人人能看）。
- 但要防"草稿被偷看"：只返回**真发布了**的（visibility=PUBLISHED 且有 currentPublishedVersionId）。

# 第①层：`PublicPostController`（HTTP 入口，新 Controller）

## 在写什么
`public` 域的新 Controller。和 `OwnerDraftController` 平级，但前缀是 `/api/v1/public`。
为什么新建而不加进 OwnerDraftController：那个是 `/owner` 前缀（要登录），这个是 `/public`（匿名），
两类安全语义不同，分开更清晰。

## 怎么做
- `@GetMapping("/posts/{postId}")`，`@PathVariable long postId`（`-parameters` 已修，能正常解析）。
- 不取登录身份，直接调 Service。

<details>
<summary>📦 参考实现</summary>

```java
package com.agentlog.content.api;

import com.agentlog.content.api.dto.response.PublicPostView;
import com.agentlog.content.application.ContentService;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

/** 公开读接口（匿名可访问，无需登录）。路径对齐 OpenAPI /api/v1/public/posts/{postId}。 */
@RestController
@RequestMapping("/api/v1/public")
public class PublicPostController {

    private final ContentService contentService;

    public PublicPostController(ContentService contentService) {
        this.contentService = contentService;
    }

    @GetMapping("/posts/{postId}")
    public PublicPostView getPost(@PathVariable long postId) {
        return contentService.getPublicPost(postId);
    }
}
```
</details>

# 第②层：`ContentService.getPublicPost()`（业务：顺指针读快照）

## 在写什么
Controller 调的业务方法。核心动作：**顺着 `post.current_published_version_id` 这个指针，找到发布版本，读它的快照块**。

回顾发布（③）干了啥：它把 `post.current_published_version_id` 指向了新建的 post_version。
所以读的时候反过来走：post → （顺指针）→ post_version → 它的 post_version_block 列表。

## 怎么做——三步（每步都对应一次查询）

**Step 1 查 post，并校验"真发布了"**（防草稿被偷看）：
```java
PostDO post = postMapper.selectById(postId);
if (post == null
        || post.getCurrentPublishedVersionId() == null              // 没发布过 → 指针为空
        || !PostVisibility.PUBLISHED.getCode().equals(post.getVisibilityStatus())) {
    throw new ApiException(ApiStatus.POST_NOT_FOUND);                // 用你扩好的枚举
}
```

**Step 2 顺指针读发布版本头**：
```java
PostVersionDO version = postVersionMapper.selectById(post.getCurrentPublishedVersionId());
```

**Step 3 读该版本的快照块（LambdaQueryWrapper，同②的套路）**：
```java
List<PostVersionBlockDO> blocks = postVersionBlockMapper.selectList(
        Wrappers.<PostVersionBlockDO>lambdaQuery()
                .eq(PostVersionBlockDO::getPostVersionId, version.getId())
                .orderByAsc(PostVersionBlockDO::getDisplayOrder));
return PublicPostView.from(postId, version, blocks);
```

> 三步只读不写，所以**不加 `@Transactional`**（和 getDraft 一样）。
> 这个方法用到的 `postVersionMapper`/`postVersionBlockMapper` 你发布时已注入构造器，直接用。

<details>
<summary>📦 参考实现（加在 ContentService）</summary>

```java
/** 读者看已发布帖：顺 post 指针读 version 快照，绝不读 draft。匿名可访问，无行级授权。 */
public PublicPostView getPublicPost(long postId) {
    PostDO post = postMapper.selectById(postId);
    if (post == null
            || post.getCurrentPublishedVersionId() == null
            || !PostVisibility.PUBLISHED.getCode().equals(post.getVisibilityStatus())) {
        throw new ApiException(ApiStatus.POST_NOT_FOUND);
    }

    PostVersionDO version = postVersionMapper.selectById(post.getCurrentPublishedVersionId());

    List<PostVersionBlockDO> blocks = postVersionBlockMapper.selectList(
            Wrappers.<PostVersionBlockDO>lambdaQuery()
                    .eq(PostVersionBlockDO::getPostVersionId, version.getId())
                    .orderByAsc(PostVersionBlockDO::getDisplayOrder));

    return PublicPostView.from(postId, version, blocks);
}
```
</details>

# 第③层：`PublicPostView`（出参，放 dto/response/）

## 在写什么
读者看到的帖子数据形状。注意所有正文/标题字段都取自**快照**（version 的 `_snapshot` 字段、block 的 `content_snapshot`），不是草稿。

## 怎么做
record + 静态 `from`。复用 ①② 已写的 `ContentBlockView`（它当初就设计成草稿和快照共用）。
放在 `dto/response/` 包（和 DraftView 同级）。

<details>
<summary>📦 参考实现</summary>

```java
package com.agentlog.content.api.dto.response;

import com.agentlog.content.infrastructure.persistence.dataobject.PostVersionBlockDO;
import com.agentlog.content.infrastructure.persistence.dataobject.PostVersionDO;
import java.time.Instant;
import java.util.List;

/** 读者看到的已发布帖详情。正文来自 post_version_block 快照（非草稿）。 */
public record PublicPostView(
        Long postId,
        String title,
        String summary,
        String channelName,
        String contentOrigin,
        Integer versionNo,
        Instant publishedAt,
        List<ContentBlockView> blocks
) {
    public static PublicPostView from(Long postId, PostVersionDO version, List<PostVersionBlockDO> blockDOs) {
        List<ContentBlockView> blocks = blockDOs.stream()
                .map(b -> new ContentBlockView(
                        b.getId(),
                        b.getDisplayOrder(),
                        b.getContentSnapshot(),   // ← 读快照字段，不是 renderedContent
                        b.getSourceTool()))
                .toList();
        return new PublicPostView(
                postId,
                version.getTitleSnapshot(),
                version.getSummarySnapshot(),
                version.getChannelNameSnapshot(),
                version.getContentOrigin(),
                version.getVersionNo(),
                version.getPublishedAt(),
                blocks);
    }
}
```
</details>

## ✅ 验证 + "发布不可覆盖"终极实验

Postman 加「6. 公开详情」：`GET /public/posts/{{postId}}`（匿名，不需要登录/CSRF）。

**终极实验（兑现整课验收）**：
1. 建草稿 → 发布 → 调公开详情，记下正文 = "今天踩了个坑……"
2. 直接改库：`UPDATE draft_block SET rendered_content='我改了草稿!' WHERE draft_id=1;`
3. 再调公开详情 → **正文仍是"今天踩了个坑……"**（没变！）
4. 查 `SELECT content_snapshot FROM post_version_block;` → 也没变

→ **证明：草稿可改，但已发布快照不可覆盖，读者读到的永远是发布那一刻的版本。** 这就是 L06 的灵魂。

> 写完 `.\mvnw -pl backend compile` 编译过，Postman 实测。
