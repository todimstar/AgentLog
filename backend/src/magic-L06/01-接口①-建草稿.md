# 接口① 建草稿 `POST /api/v1/owner/drafts`

> 本课第一个硬核。主人发帖的第一步：把"主人写的一段内容"变成数据库里的一篇草稿。
> 难点：**一个事务里，按外键顺序往 4 张表各 INSERT 一行**（TX-01）。

---

## 这一节要写 5 个文件，按调用链从上到下

```
OwnerDraftController.createDraft()      ← 你敲
   │ 入参
   ├─ CreateOwnerDraftRequest            ← 你敲（已试写）
   │
   ▼
ContentService.createOwnerDraft()  @Transactional = TX-01   ← 你敲（核心）
   │ 依次 INSERT：post → contribution → draft → draft_block
   │ 出参
   ├─ DraftView                          ← 你敲
   └─ ContentBlockView（DraftView 里的 blocks 元素）  ← 你敲
```

# 文件 1：`CreateOwnerDraftRequest`（入参 DTO）

## 【我在写什么】
接口①的**请求体**——前端建草稿时 POST 上来的 JSON 形状。

对应 OpenAPI `agentlog-openapi.yaml` 的 `CreateOwnerDraftRequest`（原文片段）：
```yaml
CreateOwnerDraftRequest:
  type: object
  required: [title, channelId, content]      # ← 这三个必填
  properties:
    title:      { type: string, maxLength: 255 }
    channelId:  { type: integer, format: int64 }
    content:    { type: string }              # 主人写的正文
    summary:    { type: [string, 'null'] }    # 可空
    tagIds:     { type: array, items: {int64} }   # ← 本课不做标签(L21)，忽略
    declaredExternalAiContent: { type: boolean }
```

## 【为什么】
- 这是接口的"进"。Controller 用它接住前端的 body。
- ⚠️ **关键澄清**：这里有个字段叫 `content`——它**不违反**"禁止 post.content"。
  - 禁的是**数据库 post 表**有 content 列。
  - 这里的 `content` 是**接口入参**（主人在输入框敲的字），后端拿到它会拆开存进
    `contribution.raw_content`（原始档案）+ `draft_block.rendered_content`（可润色块）。
  - 入参有 content 合理，库表 post 没 content，两回事。

## 【前后关系】
- 前：靠 L05 已有的 Session 认证（请求得带登录 Cookie 才能到这）。
- 后：Controller 把它转成 Service 的入参；Service 用 `title/channelId` 建 post/draft，用 `content` 建 contribution/block。
- 本课**忽略 `tagIds`**（标签是 L21），DTO 里先不放这个字段。

## 【怎么做】
你 L05 写的 `RegisterRequest` 是裸 record 没校验（手写 if）。这次升级：**用 Bean Validation 注解**做必填校验（你旧论坛 `Post.java` 上的 `@NotBlank @NotNull` 就是这套，依赖 `spring-boot-starter-validation` 你 pom 已有）。

**新知识点：record + 校验注解怎么写**
- `@NotBlank`：String 不能 null、不能空串（用于 title/content）
- `@NotNull`：不能 null（用于 channelId）
- 不标注解的字段（summary）= 可空
- 原始类型 `boolean` 默认 false，天然不为 null

<details>
<summary>📦 参考实现（先自己写，再对照）</summary>

```java
package com.agentlog.content.api.dto;

import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.NotNull;

/**
 * 建草稿请求体。字段对齐 OpenAPI CreateOwnerDraftRequest（本课忽略 tagIds，标签留到 L21）。
 *
 * content 是主人写的正文（接口入参），后端会拆存到 contribution + draft_block，
 * 不会塞进 post 表——不违反"禁止 post.content"。
 */
public record CreateOwnerDraftRequest(
        @NotBlank String title,                 // 必填：标题
        @NotNull Long channelId,                // 必填：发到哪个分区
        @NotBlank String content,               // 必填：正文
        String summary,                         // 可空：摘要
        boolean declaredExternalAiContent       // 是否声明含外部 AI 内容，默认 false
) {
}
```

# 文件 2：`ContentBlockView`（正文块视图，会被 DraftView 和 PublicPostView 复用）

## 【我在写什么】
"一个正文块"返回给前端的形状。它被嵌在 `DraftView.blocks` 和 `PublicPostView.blocks` 里。

对应 OpenAPI `ContentBlockView`（原文片段）：
```yaml
ContentBlockView:
  type: object
  required: [blockId, displayOrder, content]
  properties:
    blockId:      { type: integer, format: int64 }
    displayOrder: { type: integer }       # 块的顺序
    content:      { type: string }        # 块的正文
    author:       { $ref: AuthorView }    # ← 本课先不做作者拼装，置 null（L10 头像组才做）
    sourceTool:   { type: [string, 'null'] }
```

## 【为什么】
草稿/帖子的正文是"按块组织"的（为将来多 AI 接力，每段来自不同贡献者）。前端要逐块渲染，所以返回一个 blocks 数组，每个元素就是这个 ContentBlockView。

## 【前后关系】
- 前：它的数据来自 `draft_block` 表（接口②）或 `post_version_block` 表（接口④）。
- 后：被 DraftView（文件3）和 PublicPostView（接口④）当作 `List<ContentBlockView>` 字段。
- 本课 `author` 字段先置 null——作者头像拼装是 L10，现在做会扯出"批量查作者"的复杂度，不属于本课。

## 【怎么做】
纯数据 record。本课只填 blockId/displayOrder/content 三个，author/sourceTool 先留 null。

<details>
<summary>📦 参考实现</summary>

```java
package com.agentlog.content.api.dto;

/**
 * 单个正文块视图。被 DraftView.blocks 和 PublicPostView.blocks 复用。
 * 本课 author 先置 null（作者头像组是 L10），sourceTool 普通发帖也为 null。
 */
public record ContentBlockView(
        Long blockId,
        Integer displayOrder,
        String content,
        String sourceTool
) {
}
```
> 注：OpenAPI 里有 `author` 字段，本课暂不放（要等 L10 的 AuthorView）。
> 先少放一个字段不影响闭环，等 L10 再加——符合"本课不做什么"原则。
</details>

# 文件 3：`DraftView`（接口①②的出参）

## 【我在写什么】
"一篇草稿"返回给前端的完整形状 = **draft 表的头信息 + draft_block 表的块列表**。
它不对应单一张表，是"草稿详情"这个接口要吐给前端的一整坨。

对应 OpenAPI `DraftView`（原文片段）：
```yaml
DraftView:
  type: object
  required: [draftId, title, status, version]
  properties:
    draftId: { type: integer, format: int64 }
    title:   { type: string }
    status:  { type: string }              # EDITABLE / PUBLISHED / ...
    version: { type: integer, format: int64 }   # 乐观锁版本号
    blocks:  { type: array, items: { $ref: ContentBlockView } }
```

## 【为什么】
- 建完草稿（接口①）要返回它，前端好显示"草稿建好了，长这样"。
- 看草稿（接口②）也返回它。所以一个 View 服务两个接口。
- `version` 很关键：前端拿到后，将来发布/保存时要把它带回来做**乐观锁**校验（防并发覆盖）。

## 【前后关系】
- 前：数据来自 Service 查出来的 DraftDO（头）+ List&lt;DraftBlockDO&gt;（块）。
- 后：Service 末尾用一个静态 `from(draftDO, blockDOs)` 把 DO 翻译成这个 View 返回。
  （回顾你 L05 的 `UserView.from(account)`——同一个套路，把库对象翻译成前端对象。）

## 【怎么做】
record + 一个静态 from 方法。from 负责：draft 字段直接映射 + 把每个 DraftBlockDO 转成 ContentBlockView。

<details>
<summary>📦 参考实现</summary>

```java
package com.agentlog.content.api.dto;

import com.agentlog.content.infrastructure.persistence.dataobject.DraftBlockDO;
import com.agentlog.content.infrastructure.persistence.dataobject.DraftDO;

import java.util.List;

/**
 * 草稿视图（接口①建草稿、接口②看草稿的返回）。
 * = draft 表的头 + draft_block 表的块列表。
 */
public record DraftView(
        Long draftId,
        String title,
        String status,
        Long version,
        List<ContentBlockView> blocks
) {

    /** 把库对象翻译成前端视图（DO 永不直接返回前端，靠 from 转一道）。 */
    public static DraftView from(DraftDO draft, List<DraftBlockDO> blockDOs) {
        List<ContentBlockView> blocks = blockDOs.stream()
                .map(b -> new ContentBlockView(
                        b.getId(),
                        b.getDisplayOrder(),
                        b.getRenderedContent(),   // 草稿块的正文在 rendered_content
                        b.getSourceTool()))
                .toList();
        return new DraftView(
                draft.getId(),
                draft.getTitle(),
                draft.getStatus(),
                draft.getVersion(),
                blocks);
    }
}
```
</details>

# 文件 4：`ContentService.createOwnerDraft()`（TX-01，本课最硬核）

## 【我在写什么】
建草稿的**业务编排 + 事务**。这就是设计文档 `transaction-boundaries.md` 的 **TX-01**（原文）：
```
## TX-01 普通主人发帖
1. 创建 post(DRAFT_ONLY)；
2. 创建 contribution(author_type=OWNER)；
3. 创建 draft(EDITABLE)；
4. 创建 draft_block；
5. 返回草稿。
```

## 【为什么】
- 为什么要一个事务？因为这 4 条 INSERT **必须全成功或全失败**。
  若建了 post 却没建 draft，库里就留下"有壳没草稿"的脏数据。`@Transactional` 保证原子性
  （这你 L05 在 IdentityService 上用过，老朋友）。
- 为什么按这个顺序？**外键依赖**：draft 要指向 post（postId），draft_block 要指向 draft（draftId）
  和 contribution（contributionId）。所以被依赖的先 INSERT，拿到自增 id 再给后面用。

## 【前后关系】
- 前：Controller 把 `CreateOwnerDraftRequest` + `currentUserId` 传进来。
- 用到的地基：`ForumChannelMapper`（校验分区存在）、`PostMapper/ContributionMapper/DraftMapper/DraftBlockMapper`（上一步建好的）、`Clock`（L01 建的统一时间源）。
- 后：返回 DraftView 给 Controller。

## 【怎么做】——分步拆解（你照着敲）

**Step 0**：构造器注入 5 个 Mapper + Clock。（参考 IdentityService 的构造器注入风格）

**Step 1 校验分区存在**：
```java
ForumChannelDO channel = forumChannelMapper.selectById(cmd.channelId());
if (channel == null) throw new ApiException(NOT_FOUND, "CHANNEL_NOT_FOUND", "分区不存在");
```

**Step 2 INSERT post**（壳，状态 DRAFT_ONLY，正文字段不填）：
```java
PostDO post = new PostDO();
post.setOwnerUserId(currentUserId);      // ← 从登录态来，不信前端
post.setChannelId(cmd.channelId());
post.setVisibilityStatus("DRAFT_ONLY");
// 计数字段库表有 DEFAULT，这里可不设；created/updated/version 要设
postMapper.insert(post);                 // 插完 post.getId() 就有自增值了
```

**Step 3 INSERT contribution**（原始档案，author_type=OWNER）：
```java
ContributionDO contribution = new ContributionDO();
contribution.setAuthorType("OWNER");
contribution.setAuthorUserId(currentUserId);
contribution.setRawContent(cmd.content());   // 原始正文存这
contributionMapper.insert(contribution);
```

**Step 4 INSERT draft**（草稿头，状态 EDITABLE，指向 post）：
```java
DraftDO draft = new DraftDO();
draft.setPostId(post.getId());           // ← 用 Step2 拿到的 id
draft.setOwnerUserId(currentUserId);
draft.setTitle(cmd.title());
draft.setSummary(cmd.summary());
draft.setChannelId(cmd.channelId());
draft.setStatus("EDITABLE");
draftMapper.insert(draft);
```

**Step 5 INSERT draft_block**（正文块，指向 draft + contribution）：
```java
DraftBlockDO block = new DraftBlockDO();
block.setDraftId(draft.getId());
block.setContributionId(contribution.getId());
block.setAuthorType("OWNER");
block.setAuthorUserId(currentUserId);
block.setDisplayOrder(0);                // 第一块，顺序 0
block.setRenderedContent(cmd.content()); // 可润色副本，初始 = 原始内容
block.setIsHidden(false);
draftBlockMapper.insert(block);
```

**Step 6 返回**：`return DraftView.from(draft, List.of(block));`

> ⚠️ 每个 DO 别忘了设 `createdAt/updatedAt`（用 `Instant.now(clock)`）和 `version`（设 0L）。
> 库表这些列是 `NOT NULL` 没 DEFAULT，不设会插入失败——这是你会踩的第一个真坑，故意不写进上面片段，留给你 debug。

<details>
<summary>📦 完整参考实现（先自己写，卡住再看）</summary>

```java
package com.agentlog.content.application;

import com.agentlog.content.api.dto.CreateOwnerDraftRequest;
import com.agentlog.content.api.dto.DraftView;
import com.agentlog.content.infrastructure.persistence.dataobject.*;
import com.agentlog.content.infrastructure.persistence.mapper.*;
import com.agentlog.shared.error.ApiException;
import java.time.Clock;
import java.time.Instant;
import java.util.List;
import org.springframework.http.HttpStatus;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

/**
 * content 模块应用服务：编排发帖相关事务。
 * 分层：Controller 只接 HTTP，这里负责业务编排 + 事务，Mapper 只持久化。
 */
@Service
public class ContentService {

    private final ForumChannelMapper forumChannelMapper;
    private final PostMapper postMapper;
    private final ContributionMapper contributionMapper;
    private final DraftMapper draftMapper;
    private final DraftBlockMapper draftBlockMapper;
    private final Clock clock;

    public ContentService(
            ForumChannelMapper forumChannelMapper,
            PostMapper postMapper,
            ContributionMapper contributionMapper,
            DraftMapper draftMapper,
            DraftBlockMapper draftBlockMapper,
            Clock clock) {
        this.forumChannelMapper = forumChannelMapper;
        this.postMapper = postMapper;
        this.contributionMapper = contributionMapper;
        this.draftMapper = draftMapper;
        this.draftBlockMapper = draftBlockMapper;
        this.clock = clock;
    }

    /** TX-01 普通主人发帖：一个事务里按外键顺序建 post→contribution→draft→draft_block。 */
    @Transactional
    public DraftView createOwnerDraft(long currentUserId, CreateOwnerDraftRequest cmd) {
        Instant now = Instant.now(clock);

        // 1. 校验分区存在（外键虽也会拦，但提前校验给出更友好的业务错误）
        ForumChannelDO channel = forumChannelMapper.selectById(cmd.channelId());
        if (channel == null) {
            throw new ApiException(HttpStatus.NOT_FOUND, "CHANNEL_NOT_FOUND", "分区不存在");
        }

        // 2. 建 post（壳，DRAFT_ONLY，不存正文）
        PostDO post = new PostDO();
        post.setOwnerUserId(currentUserId);
        post.setChannelId(cmd.channelId());
        post.setVisibilityStatus("DRAFT_ONLY");
        post.setIterationCount(0);
        post.setViewCount(0L);
        post.setLikeCount(0L);
        post.setCommentCount(0L);
        post.setCollectionCount(0L);
        post.setHotScore(java.math.BigDecimal.ZERO);
        post.setIsPinned(false);
        post.setIsEssence(false);
        post.setVersion(0L);
        post.setCreatedAt(now);
        post.setUpdatedAt(now);
        postMapper.insert(post);

        // 3. 建 contribution（不可变原始贡献，OWNER）
        ContributionDO contribution = new ContributionDO();
        contribution.setAuthorType("OWNER");
        contribution.setAuthorUserId(currentUserId);
        contribution.setRawContent(cmd.content());
        contribution.setCreatedAt(now);
        contributionMapper.insert(contribution);

        // 4. 建 draft（草稿头，EDITABLE）
        DraftDO draft = new DraftDO();
        draft.setPostId(post.getId());
        draft.setOwnerUserId(currentUserId);
        draft.setTitle(cmd.title());
        draft.setSummary(cmd.summary());
        draft.setChannelId(cmd.channelId());
        draft.setStatus("EDITABLE");
        draft.setDeclaredExternalAiContent(cmd.declaredExternalAiContent());
        draft.setVersion(0L);
        draft.setCreatedAt(now);
        draft.setUpdatedAt(now);
        draftMapper.insert(draft);

        // 5. 建 draft_block（正文块，指回 draft + contribution）
        DraftBlockDO block = new DraftBlockDO();
        block.setDraftId(draft.getId());
        block.setContributionId(contribution.getId());
        block.setAuthorType("OWNER");
        block.setAuthorUserId(currentUserId);
        block.setDisplayOrder(0);
        block.setRenderedContent(cmd.content());
        block.setIsHidden(false);
        block.setVersion(0L);
        block.setCreatedAt(now);
        block.setUpdatedAt(now);
        draftBlockMapper.insert(block);

        // 6. 翻译成视图返回
        return DraftView.from(draft, List.of(block));
    }
}
```

# 文件 5：`OwnerDraftController.createDraft()`（接口入口）

## 【我在写什么】
接口①的 HTTP 入口。对应 OpenAPI 路径 `POST /api/v1/owner/drafts`，返回 `DraftView`。

## 【为什么】
- Controller 只做三件事：拿当前登录用户 → 调 Service → 返回结果。**不放业务逻辑**（业务在 Service）。
- 这是你最熟的层（旧论坛你天天写 Controller）。

## 【前后关系】
- 前：靠 L05 的安全配置——`/api/v1/owner/**` 已被 `anyRequest().authenticated()` 兜住，没登录到不了这。
- 关键：用 `CurrentUser.requireId()` 拿 currentUserId（**不接受前端传 owner id**，这是设计文档 P0 授权铁律）。
- 后：调 `contentService.createOwnerDraft(currentUserId, request)`。

## 【怎么做】
- `@RestController` + `@RequestMapping("/api/v1/owner")`
- `@PostMapping("/drafts")` + `@ResponseStatus(CREATED)`（建资源返回 201，对齐你 L05 register 的写法）
- 参数 `@Valid @RequestBody CreateOwnerDraftRequest`——`@Valid` 触发那些 `@NotBlank` 校验，
  校验失败自动抛异常 → 你 L05 的 GlobalExceptionHandler 转成 problem+json。

<details>
<summary>📦 参考实现</summary>

```java
package com.agentlog.content.api;

import com.agentlog.content.api.dto.CreateOwnerDraftRequest;
import com.agentlog.content.api.dto.DraftView;
import com.agentlog.content.application.ContentService;
import com.agentlog.shared.security.CurrentUser;
import jakarta.validation.Valid;
import org.springframework.http.HttpStatus;
import org.springframework.web.bind.annotation.*;

/**
 * 主人草稿接口。路径对齐 OpenAPI /api/v1/owner/drafts。
 * Controller 只做 HTTP 编排：拿登录身份 → 调 Service → 返回视图。
 */
@RestController
@RequestMapping("/api/v1/owner")
public class OwnerDraftController {

    private final ContentService contentService;

    public OwnerDraftController(ContentService contentService) {
        this.contentService = contentService;
    }

    @PostMapping("/drafts")
    @ResponseStatus(HttpStatus.CREATED)
    public DraftView createDraft(@Valid @RequestBody CreateOwnerDraftRequest request) {
        // 行级授权铁律：owner 从登录态取，绝不信前端传的 id
        long currentUserId = CurrentUser.requireId();
        return contentService.createOwnerDraft(currentUserId, request);
    }
}
```
</details>
