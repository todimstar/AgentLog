📝 课后测验 · 单机娘 Skill 自动投稿

    
由浅入深 5 题。先自己说出答案再点开对照——能讲顺 = 真懂了，卡壳的题回到对应线重听。

    
①基础L14 的硬验收线之一是「Agent 无 publish」。为什么机娘只能投草稿、不能自己发布？
      
发布权永远属于人类主人。机娘（AI）写的内容必须经主人审阅、亲手点发布才能公开——这是 AgentLog 的产品安全底线。落到代码上：/api/v1/agent/** 下只有建草稿一个动作，根本没有 publish 端点；发布只在主人的 POST /owner/drafts/{id}/publish（走 Session）。机娘建的草稿 owner_user_id 填的是机娘背后的主人，于是这篇稿天然落进那个主人的草稿箱，只有他能看、审、发。

    
②考古契约里明明已经有一个机娘 submit 接口，为什么这一课还要新建一个？
      
契约里那个 submit 是 POST /agent/contribution-tickets/{ticketCode}/contributions，返回带 ticketCode/nextHandoffToken——全是 L15/L16 多机娘 ACPP 协作的概念（席位、下一棒交接）。而 L14 的验收线是「不写多机娘接力」。查三份权威文档（用例矩阵/范围与阶段/course_schedule）一致证明：单机娘投稿本就是独立用例，是活契约漏画了它、把它跟协作 submit 混成一个。定性同 L13.5 的 L10 缺席——以权威蓝图为准，补画独立端点 POST /agent/drafts + 登记漂移 D-13，不是照残缺的契约做。

    
③架构content 模块的控制器要读机娘身份，但 AgentPrincipal 在 identity 私有包里。直接 import 会怎样？正解是什么？
      
直接 @AuthenticationPrincipal AgentPrincipal 会让 content → identity 私有子包产生跨模块依赖，被 ModularityTest（Spring Modulith + ArchUnit 静态校验包依赖）判红。正解是依赖倒置（DIP）：在 shared.security（OPEN 模块，人人可依赖）定义只读接口 AgentIdentity，让 AgentPrincipal implements AgentIdentity（record 自动提供实现，L13 逻辑零改动）。content 的控制器用 @AuthenticationPrincipal AgentIdentity——只依赖 shared 的接口，不碰 identity 的实现类。identity→shared 合法、content→shared 合法，零跨业务模块依赖。

    
④设计owner 投稿和 agent 投稿的落库逻辑几乎一样，怎么复用又不把认证关注点漏进业务层？
      
把「建 Post 指针 + 不可变 Contribution + Draft 头 + DraftBlock」这套公共动作抽成 私有内核 createDraftInternal(DraftAuthor author, ...)，唯一差别——谁写的——用一个 DraftAuthor 参数对象（record）传入。createOwnerDraft/createAgentDraft 各是一层薄封装：owner 版填 authorUserId、agent 维度留 null；agent 版填 authorAgentId+sourceTool+clientRunId，归属键填机娘背后的主人。作者身份从令牌 principal 派生、不从请求体传——防伪造，同 owner 侧 currentUserId 从 Session 派生的思路。

    
⑤综合把 skill / CLI / 后端串起来，机娘一次投稿的完整链路是怎样的？令牌在哪些环节出现、又如何不泄漏？
      
skill（指令文件夹）告诉 AI 工具：auth status→（必要时 auth login）→agents list→主人选机娘→agent assume 拿机娘令牌→收集证据→agentlog submit --file 投稿→把草稿地址回主人+提醒审稿。CLI submit 取本地存的 acting token、读正文文件，带 Bearer 机娘令牌调 POST /agent/drafts（走 Chain 3）。后端验币→AgentPrincipal 入上下文→createAgentDraft 落库（author_type=AGENT）→拼 draftUrl 返回。令牌全程只写本地文件、绝不打印：CLI 的 stdout 只吐含 draftUrl 的机器可读 JSON，token 不进控制台/日志（沿用 L13 铁律）。多机娘接力（collab）被裁掉，留 L15。
