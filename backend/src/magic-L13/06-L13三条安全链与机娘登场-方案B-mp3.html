📝 课后测验 · 三条安全链与机娘登场

    
由浅入深 5 题。先自己说出答案再点开对照——能讲顺 = 真懂了，卡壳的题回到对应线重听。

    
①基础L12 明明铸出了有效的 owner 令牌，为什么 L13 之前拿它敲 /cli/** 还是 401？
      
因为 L05 建的唯一那条安全链只认浏览器的 Session Cookie。CLI 没有 Cookie、没有 Session，它手里只有一枚 Bearer 令牌，而后端根本没有任何一段代码去读它、认它。令牌是真的，可没有「消费端」。L13 第一件事就是造 Chain 2 这条只认 Bearer 的链，把 L12 铸的币花掉 → 对应视频「第一幕·401 悬念」。

    
②链路为什么不在一条链里「顺便」也认 Bearer？Spring 又是怎么决定一个请求归哪条链的？
      
不能塞一条链：Web 与 Bearer 配置天生矛盾——会话要 IF_REQUIRED(有状态) vs STATELESS；CSRF 要开(Cookie 怕伪造) vs 要关(Bearer 无 CSRF 面)。同一条链没法对不同请求各配一套。选链靠 securityMatcher + @Order：Spring 按 Order 从小到大问每条链「这 URL 匹配你吗」，第一个说匹配的独占接管。选哪条链只看 URL、在碰令牌之前就定了——matcher 决定「谁接管」，过滤器决定「接管后怎么认」，两件事别混。

    
③原理Chain 2 的过滤器怎么「验币」？为什么不用 Spring 现成的 OAuth2 Resource Server？
      
验币 = 铸币反着来：拿客户端传的明文令牌，用 L12 同一个 tokenService.digest() 再算一遍 HMAC 摘要，按 access_token_digest 查 owner_access_session；命中且 ACTIVE+未过期 → 造 OwnerPrincipal 入 SecurityContext（OwnerBearerAuthenticationFilter L62-79）。不用 OAuth2 RS：它是为 JWT(自解释) 或 introspection(调授权服务器) 设计的；我们的令牌是 opaque 随机串，有效性只查自己的表比对摘要。自写一个 OncePerRequestFilter 透明可控好教（ADR-0001）。

    
④设计什么是 RTR（refresh 令牌轮换）？为什么「重放一枚已轮换的 refresh」要连坐吊销整台设备？
      
RTR=每次 refresh 发新 access + 新 refresh，旧会话置 REVOKED（OwnerSessionService L72-91），OAuth BCP 推荐。好处：每枚 refresh 寿命短，且能检测盗用。连坐吊销：一枚已被合法轮换掉（REVOKED）的 refresh 又被拿来用，只有一种解释——它被复制了，攻击者和真 CLI 各持一份，无法分辨谁真。最安全的反应是吊销该 installation 名下所有 ACTIVE 会话（owner+机娘一起废，L60-61），强制重新配对。用旧令牌重放，反而成了发现盗用的信号。

    
⑤综合机娘 assume 的命根子是什么？失败为何返回 404 而非 403？本课那个「双重注册」坑教训是什么？
      
命根子：只能代入 agent_account.owner_user_id == 当前 owner 令牌的 ownerUserId 且机娘 ACTIVE 的机娘（AgentAssumeService L56）——用根身份换一把窄的机娘令牌，STS AssumeRole 式代入。404 而非 403：连「这个机娘存在」都不泄漏给你（防枚举）。双重注册坑：OncePerRequestFilter 一旦标 @Component 会被注册两次，其中一次对所有 URL 全局生效，导致 agent filter 全局拦截 /cli/** 请求误判 401。教训：只属于某条 SecurityFilterChain 的过滤器别做成 Spring bean——改用 new 构造、限定进本链。
