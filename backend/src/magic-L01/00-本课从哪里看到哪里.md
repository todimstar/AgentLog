# L01 后端最小启动：课堂路线

这节课只解决一个问题：后端作为一个服务，能不能证明自己“活着”。

先把边界钉住：本课不做登录、不做数据库表、不做论坛业务。Security 和错误处理只搭“骨架”，不提前讲完整认证。

## 先看这张小黑板

```text
旧论坛 springBootDemo
  SecurityConfig
    -> JWT 过滤器
    -> 登录/注册/公开查询 permitAll
    -> 其他 authenticated

  Result<T> / ErrorResponse
    -> { code, message, data }
    -> 业务错误再塞进 data

AgentLog L01
  ApiSecurityConfiguration
    -> 还没有 JWT
    -> 只放行 health / ping
    -> 其他 denyAll

  ProblemDetail
    -> RFC 9457: application/problem+json
    -> type/title/status/detail 是标准骨架
    -> code/traceId/recoverable 是项目扩展字段
```

一句话：旧项目是“自定义响应包装”，AgentLog 是“HTTP 标准错误文档 + 项目错误码扩展”。

## 本课从哪里看到哪里

```text
0. 01-旧论坛对照-Security与错误码.md
   先复习旧项目影子，知道这次哪些地方像、哪些地方故意不同。

1. pom.xml
   先看父工程：Java 21 和 UTF-8 是否真正落到 Maven 编译。

2. backend/pom.xml
   再看后端模块：它是否具备 Spring Boot 启动/打包能力。

3. backend/src/main/resources/application.yml
   再看启动配置：L01 暂时切开“后端活着”和“数据库活着”。

4. backend/src/main/java/com/agentlog/interfaces/SystemController.java
   再看 ping：项目自己的最小探针。

5. backend/src/main/java/com/agentlog/shared/time/TimeConfiguration.java
   再看 Clock：统一时间来源。

6. backend/src/main/java/com/agentlog/shared/security/ApiSecurityConfiguration.java
   再看 Security：Spring Security 默认会拦，L01 只放行 health 和 ping。

7. backend/src/main/java/com/agentlog/shared/error/*
   再看 ProblemDetail：不是旧 Result<T>，而是 RFC 9457 风格。

8. backend/src/test/java/*
   最后看测试：证明 health、ping、ProblemDetail 真的成立。
```

阅读方式：

```text
先读本文件。
再读 01-旧论坛对照-Security与错误码.md。
然后逐个打开镜像路径中的讲义文件。
每个讲义文件都写了：正式目标文件、定位上下文、要替换/新增的代码、为什么这么改。
```

目录里的文件不是可直接编译源码，而是“带定位上下文的课堂改动说明”。
