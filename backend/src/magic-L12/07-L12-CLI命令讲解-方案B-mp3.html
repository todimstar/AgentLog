📝 课后测验 · CLI 命令行工具

    
由浅入深 5 题。先自己说出答案再点开对照——能讲顺 = 真懂了，卡壳的题回到对应线重听。

    
①基础CLI 是什么？在哪里跑？和浏览器 / 前端网页是什么关系？
      
CLI = 命令行工具，是 AI 工具的「手」——一个终端程序，被动执行命令，不在浏览器里、不在前端网页里。配对时「一手终端、一手浏览器」：终端跑 agentlog auth login 拿配对码，浏览器开 /#/cli-pair 输码批准，终端那头自动完成。前端 /settings 的提示只告诉你「批准页在哪」，不是让你在前端跑 CLI。

    
②链路auth login 分哪几步？为什么中间要「轮询」？
      
四步（AuthCommand.Login）：① L53 POST 发起配对拿 deviceCode+userCode+verificationUri；② L66-67 打印批准网址+配对码给你；③ L73 起轮询循环，每隔 pollInterval 秒 POST 问一次「批了没」；④ L82 APPROVED → L85 存令牌返回。为什么轮询：CLI 不知道你什么时候在浏览器点批准，只能不停问——你在终端看到的那排小点（L102）就是 PENDING 时打的。

    
③设计config.json 和 credentials.json 为什么分成两个文件？各存什么？
      
按「密 / 非密」分家：config.json（CliConfig）存非密的 serverBaseUrl + installationCode；credentials.json（CredentialStore）存敏感的 owner access/refresh 令牌（⚠ 明文存·非加密）。分开的好处：可对 credentials 单独收紧文件权限（L88 POSIX rw-------）、非密配置能放心人工查看/编辑、职责清晰。对齐 Pack 的 config.schema / credentials.schema 两份 schema。

    
④设计同一台机器跑多个 CLI（如 Claude Code + Codex）怎么互不干扰？installationCode 和 AGENTLOG_HOME 各起什么作用？
      
installationCode（CliConfig L58）= 这台 CLI 的设备身份，首次随机生成并持久化 → 每个 CLI 实例一个 → 后端按它建独立的 client_installation、独立配对、独立 owner 令牌。AGENTLOG_HOME（CliPaths L23）= 决定配置/凭据存哪个目录：每个 CLI / skill 设不同的 AGENTLOG_HOME，就各存各的、互不覆盖。两者配合实现「同机多 CLI 隔离」。（机娘身份的隔离是另一层：L13 assume 按 agent+tool+run 区分。）

    
⑤安全令牌在 CLI 侧怎么保护？为什么 stdout 和 stderr 要分开？
      
令牌保护（⚠ 明文存·非加密——V0 无静态加密，靠下面两道非加密的墙，生产才接 Keychain）：只写 credentials.json、绝不打印到控制台/日志（翻遍 login 找不到 print 令牌的行）；写文件尽力收紧权限仅本人可读（L88，Windows 不支持则优雅跳过，生产改 ACL）。stdout/stderr 分开（cli-spec）：stdout 出机器可读 JSON（供脚本/AI 工具解析），stderr 出人类诊断（提示、进度点、错误）——这样管道里 agentlog ... | jq 拿到的是干净 JSON，不被提示文字污染。刷新令牌（refresh）换新 access 是 L13。
